MotivaçãoPor que começar pela lógica?

Neste módulo você vai construir aplicativos de verdade desde o começo — telas que recebem o que a pessoa digita, escolhe e marca, e respondem na hora. Nada de resultado escondido numa janela de texto preta: tudo aparece na tela, do jeito que um app funciona.

Mas repare no que está sendo treinado: não é a parte visual, é o miolo. Cores, animações, layout refinado e navegação entre páginas ficam para as unidades seguintes do curso. Aqui a interface é montada com o mínimo necessário — um campo de texto, uma lista de opções, uma caixinha de marcar, um botão e um cartão de resultado — justamente para que a sua atenção fique onde importa agora: o que o app decide fazer com os dados que recebeu.

Essa é a habilidade que não tem atalho. Copiar uma tela bonita de um tutorial é fácil; fazer o app cobrar o frete certo, validar o cadastro sem deixar brecha e calcular o desconto sem errar centavo é o que realmente se aprende programando. É disso que trata o resto desta apostila.

Lógica de programação é a habilidade de quebrar um problema em passos pequenos, exatos e na ordem certa — do jeito que um computador precisa, porque ele não "adivinha" nada.

Pense no Dart como o idioma e no Flutter como a oficina: as ferramentas, as peças prontas e a máquina que monta o aplicativo no final. Você escreve em Dart; o Flutter constrói.

Um código, várias plataformas

A grande vantagem do Flutter é que o mesmo código pode virar um app Android, um app de iPhone, um site ou um programa de computador. Não é preciso reescrever o aplicativo do zero para cada lugar — e é por isso que o curso se chama Desenvolvedor Mobile mas a gente vai poder treinar no navegador.

Por que vamos começar pela web

Rodar no navegador é o caminho mais curto entre escrever uma linha de código e vê-la funcionando:

  • Não precisa de celular nem de emulador. O app abre numa aba do Chrome, como qualquer site.
  • Não precisa instalar o Android Studio (que é grande e demorado) só para treinar lógica.
  • A lógica é exatamente a mesma. Um if ou um for escrito hoje na web funciona igualzinho no app Android depois: mesmo Dart, mesmo Flutter.
Em bom português

No Flutter, tudo que aparece na tela é um widget — um bloquinho de interface, como peças de Lego que se encaixam para formar a tela inteira. Um texto é um widget, um botão é um widget, a caixinha de marcar é um widget. Por enquanto você só vai usar widgets já prontos, sem precisar criar os seus.

No mercado

Empresas de todos os tamanhos usam Flutter justamente por esse "escreve uma vez, publica em vários lugares", que reduz custo e tempo de manutenção. Para quem está começando, isso significa que o que você aprender aqui não serve para uma plataforma só.

Flutter · 2Como o Flutter pensa

Antes de escrever código, vale entender uma ideia que muda tudo — e que costuma ser o maior tropeço de quem vem de outras linguagens. No Flutter você não manda a tela mudar. Você descreve como ela deve ser, e ele cuida do resto.

Mandar fazer x descrever o resultado

Imagine que você precisa arrumar uma mesa de restaurante. Existem dois jeitos de pedir isso:

Declarativo — como o Flutter funciona

"A mesa arrumada tem toalha, dois pratos e quatro taças."

Você descreve como deve ficar. Quem executa compara com o estado atual e faz só o que falta.

Imperativo — o que NÃO fazemos aqui

"Pegue a toalha. Estenda. Agora pegue um prato. Coloque à esquerda. Agora o outro..."

Você comanda cada passo. Se algo já estava na mesa, o risco de bagunça é seu.

Em bom português

Linguagem declarativa quer dizer que o seu código declara (descreve) o resultado desejado, em vez de dar a sequência de ordens para chegar nele. No Flutter, a função build é essa descrição: ela responde à pergunta "com os dados que eu tenho agora, como esta tela deve aparecer?".

Por isso, no molde que vamos usar, você nunca vai encontrar um comando do tipo "mude o texto do cartão". O que existe é: a gaveta resultado passa a valer outra coisa, e a tela é descrita de novo já com esse valor novo.

A tela é uma função do estado

Essa é a frase que resume o Flutter inteiro, e vale guardar:

A regra de ouro

tela = f(estado)

Estado são os dados que podem mudar enquanto o app está aberto: o que foi digitado, o que foi escolhido, o que está marcado. Dado o estado, a tela é sempre a mesma — mesma entrada, mesmo desenho. Mudou o estado, o Flutter redesenha.

Cuidado

Este é o erro número um de quem começa: mudar uma gaveta fora do setState. O valor muda de verdade na memória, mas ninguém avisou o Flutter — então o build não roda, a tela não é redesenhada e parece que "o código não funcionou". Se algo mudou por dentro e não apareceu na tela, procure um setState faltando.

Tudo é widget, e widgets se encaixam

A tela inteira é montada encaixando widgets uns dentro dos outros, como peças de Lego. O widget de fora segura os de dentro, e é por isso que o código tem tanta indentação. Esta é a estrutura do molde que você vai colar no próximo capítulo:

a árvore de widgets do molde

Scaffold                  o esqueleto da tela
├─ AppBar                 a barra azul do topo
└─ SingleChildScrollView  permite rolar quando não cabe
   └─ Column              empilha os filhos de cima para baixo
      ├─ TextField        campo de digitação
      ├─ ElevatedButton   botão
      └─ Card             o cartão do resultado
         └─ Text          o texto dentro do cartão
Em bom português

Essa estrutura de encaixe se chama árvore de widgets. Widgets que seguram um filho usam o parâmetro child: (o Card acima segura um Text). Os que seguram vários usam children:, com a lista entre colchetes (a Column acima). Essa é a diferença entre as duas palavras que mais confundem no começo.

Com memória e sem memória

StatelessWidget — sem memória

Desenha sempre a mesma coisa a partir do que recebeu. Não guarda nada que mude. No molde, é o AppTreino, que só liga o aplicativo.

StatefulWidget — com memória

Tem gavetas que mudam enquanto o app roda e pode chamar setState para se redesenhar. É a nossa Tela, onde acontece tudo.

Em bom português

Repare que o StatefulWidget vem sempre em dupla: uma classe para o widget e outra, com o nome terminando em State, para guardar o estado e desenhar. É burocracia da linguagem — o Flutter precisa poder jogar o widget fora e recriá-lo sem perder o que estava guardado. Por enquanto é só copiar o formato do molde.

Cuidado

A função build pode rodar muitas vezes por segundo — a cada mudança de estado, ao girar a tela, ao aparecer o teclado. Por isso ela só deve descrever a tela. Cálculos demorados, gravar arquivo ou pedir dados na internet não vão ali dentro; no nosso molde, esse tipo de coisa fica na função calcular(), que só roda quando o botão é apertado.

Flutter · 3Instalando o Flutter (Windows)

Esta é a única parte chata do módulo, e ela acontece uma vez só. Se o computador do laboratório já tiver o Flutter instalado, pule direto para o próximo capítulo.

  1. Instale o Git para Windows. Baixe em git-scm.com/download/win e avance com as opções padrão. O Flutter usa o Git por dentro, então ele precisa estar instalado antes.
  2. Instale o Google Chrome, se ainda não tiver. É nele que nossos apps vão abrir.
  3. Baixe o SDK do Flutter na página oficial docs.flutter.dev/get-started/install/windows, escolhendo a opção de desenvolvimento web. É um arquivo .zip grande — pode demorar para baixar.
  4. Descompacte numa pasta simples, por exemplo C:\dev\flutter. Evite C:\Program Files e evite caminhos com espaços ou acentos — é uma fonte clássica de erro difícil de achar depois.
  5. Coloque o Flutter no PATH. No menu Iniciar, procure "variáveis de ambiente" → Editar as variáveis de ambiente para a sua conta → selecione Path → Editar → Novo → digite C:\dev\flutter\bin → OK em todas as janelas.
  6. Abra um terminal novo (PowerShell) e rode flutter doctor. Na primeira vez ele baixa alguns componentes e depois mostra um relatório do que está pronto e do que falta.
  7. Instale o VS Code e, dentro dele, a extensão Flutter (ela já traz a do Dart junto). Vai ser o nosso editor no curso.
Em bom português

Terminal é aquela janela preta onde a gente digita comandos em texto em vez de clicar em botões. E PATH é a lista de pastas onde o Windows procura programas quando você digita um comando ali. Colocar C:\dev\flutter\bin nessa lista é justamente o que faz o comando flutter funcionar de qualquer pasta.

Cuidado

O flutter doctor quase certamente vai reclamar de coisas como Android toolchain, Android Studio ou Visual Studio, com um X vermelho. Isso não é problema para nós. Essas partes só são necessárias para gerar apps de Android, iPhone ou Windows. Para treinar lógica no navegador, basta que a linha do Chrome apareça com o visto verde.

Cuidado

Se o terminal responder algo como "flutter: o termo não é reconhecido", quase sempre é uma de duas coisas: o caminho digitado no PATH está errado, ou você ainda está num terminal que foi aberto antes da mudança. Feche e abra o terminal de novo antes de tentar qualquer outra coisa.

Flutter · 5O molde do app de treino

Agora vamos trocar o app de exemplo por um molde enxuto: um campo, um botão e um cartão que mostra o resultado. Todo exercício deste material nasce desse mesmo molde — muda só o que está dentro das três regiões marcadas.

Abra o lib/main.dart, apague tudo o que estiver lá e cole o código abaixo.

lib/main.dart — o molde

cole uma vez só
import 'package:flutter/material.dart';

void main() => runApp(const AppTreino());

class AppTreino extends StatelessWidget {
  const AppTreino({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: "Treino de Lógica",
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const Tela(),
    );
  }
}

class Tela extends StatefulWidget {
  const Tela({super.key});

  @override
  State<Tela> createState() => _TelaState();
}

class _TelaState extends State<Tela> {
  // ===== 1. AS GAVETAS: o que a tela precisa guardar =====
  String resultado = "";

  // ===== 2. A LÓGICA: o que acontece ao apertar o botão =====
  void calcular() {
    setState(() {
      resultado = "Tudo pronto! Agora é só programar aqui dentro.";
    });
  }

  // ===== 3. A TELA: o que a pessoa vê =====
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text("Treino de Lógica")),
      body: SingleChildScrollView(
        padding: const EdgeInsets.all(24),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            // os campos de preenchimento entram aqui

            ElevatedButton(
              onPressed: calcular,
              child: const Text("Calcular"),
            ),
            const SizedBox(height: 24),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Text(resultado, style: const TextStyle(fontSize: 18)),
              ),
            ),
          ],
        ),
      ),
    );
  }
}
Em bom português

O molde tem três regiões numeradas, e é só nelas que você mexe no material inteiro:

  1. As gavetas — as variáveis que a tela guarda (o que a pessoa digitou, o resultado a mostrar).
  2. A lógica — a função calcular(), que roda quando o botão é apertado. É o coração de tudo que você vai aprender.
  3. A tela — a lista de widgets que aparecem, de cima para baixo.

O resto do arquivo é encanamento: ele liga o app e cria a janela. Vamos destrinchar esse encanamento nas unidades de Flutter.

As três regiões conversam entre si: a gaveta resultado é escrita pela lógica e lida pelo cartão da região 3. Se você apagar uma gaveta que a região 3 usa, aparece erro vermelho — por isso os exercícios sempre mostram as três regiões que precisam mudar juntas.

Em bom português

setState é o comando que avisa o Flutter: "mudei uma gaveta, redesenhe a tela". Sem ele, o valor muda por dentro mas a tela continua mostrando o antigo. Toda vez que você quiser ver algo novo aparecer, a mudança precisa acontecer dentro de um setState.

Dois ajustes de uma vez só

Logo após colar o molde, o VS Code vai apontar dois "problemas" que são só sobras do projeto de exemplo. Resolva agora e não pense mais neles:

  1. Apague a pasta test/. Ela tem um teste de exemplo que aponta para o código antigo do lib/main.dart — o que acabamos de substituir. Sem apagar, ela fica marcada com erro vermelho para sempre. Testes automatizados são assunto de outra unidade do curso.
  2. Libere o print() (opcional). Se você usar print() para espiar valores, o projeto mostra um aviso amarelo recomendando não usá-lo em apps publicados. Para desligar: abra o analysis_options.yaml na raiz do projeto, encontre a linha # avoid_print: false e apague o # e o espaço depois dele, deixando só avoid_print: false recuado como estava.
Cuidado

Erro vermelho e aviso amarelo são coisas diferentes. O vermelho impede o app de rodar e precisa ser corrigido. O amarelo (ou azul) é só uma sugestão de estilo: o app roda normalmente. Saber diferenciar os dois evita muito desespero desnecessário no começo.

Em bom português

Existe também o print("alguma coisa"), o comando clássico do Dart para escrever uma mensagem. Ela não aparece no app: vai para o Debug Console do VS Code. Neste material o resultado sempre aparece na tela, mas guarde o print() no bolso — ele é ótimo para espiar o valor de uma variável quando algo não funciona como você esperava.

Mão na massa

Rode o app (flutter run -d chrome), clique em Calcular e veja a mensagem aparecer no cartão. Agora troque o texto dentro do setState por outro qualquer, salve com Ctrl+S e clique de novo. Viu mudar? Seu ambiente está pronto.

Flutter · 6Lendo e escrevendo código Flutter

Agora que você tem o molde na tela, vale parar cinco minutos para aprender a ler aquilo. Código Flutter assusta no começo por causa da indentação e da escadinha de parênteses no fim — mas tem um padrão só, que se repete até o fim do curso.

A anatomia de um widget

Toda chamada de widget tem a mesma forma: o nome, e dentro dos parênteses uma lista de parâmetros nomeados, cada um com nome, dois-pontos e valor.

sempre o mesmo formato

ElevatedButton(          // nome do widget
  onPressed: calcular,   // parâmetro "onPressed" recebe a função
  child: const Text(     // parâmetro "child" recebe OUTRO widget
    "Calcular",          //   que por sua vez recebe um texto
  ),
)                        // fecha o ElevatedButton
Em bom português

Parâmetro nomeado é aquele que você passa dizendo o nome dele: onPressed: calcular. É o contrário de passar só o valor na ordem certa, como em calcularMedia(7.0, 8.5). Quase tudo no Flutter é nomeado — o que deixa o código mais longo, mas muito mais fácil de ler: você não precisa decorar que "o terceiro valor é a cor".

A vírgula do fim faz o código se arrumar sozinho

Repare que, nos exemplos, o último parâmetro também tem vírgula antes do parêntese de fechamento. Isso não é descuido: é o que faz o formatador automático quebrar o código em linhas legíveis, em vez de amontoar tudo numa linha só.

Com vírgula no fim

Card(
  child: Text(resultado),
)

O formatador empilha, e dá para ver onde cada widget começa e termina.

Sem vírgula no fim

Card(child: Text(resultado))

Funciona igual, mas conforme o widget cresce vira uma linha enorme, difícil de ler e de achar erro.

Atalho que salva a vida

Para o VS Code arrumar a indentação do arquivo inteiro, aperte Shift + Alt + F. Faça isso sempre que o código parecer embaralhado: se ele se arrumar bonitinho, os parênteses e chaves estão equilibrados; se o formatador não fizer nada, é sinal de que falta fechar alguma coisa — o que já é uma pista e tanto sobre onde está o erro.

A escada de parênteses

Como os widgets ficam encaixados uns dentro dos outros, o fim de um trecho costuma ter uma sequência assim:

o fechamento do molde, de dentro para fora

            ),   // fecha o Text
          ),     // fecha o Padding
        ),       // fecha o Card
      ],         // fecha a lista children
    ),           // fecha a Column
  ),             // fecha o SingleChildScrollView
);               // fecha o Scaffold e o return
Em bom português

Cada linha dessas fecha um widget, de dentro para fora. Você não precisa contar na mão: clique num parêntese e o VS Code destaca o par dele. A indentação também ajuda — o fechamento fica alinhado com a linha que abriu. E lembre: ] fecha lista (children:) e ) fecha chamada de widget.

O const que o editor fica sugerindo

Você vai ver const espalhado pelos exemplos: const Text("Calcular"). Ele marca um widget que nunca muda, e o Flutter aproveita isso para não redesenhá-lo à toa.

Em bom português

A regra prática: se o conteúdo é fixo, escrito ali no código, cabe const (const Text("Calcular")). Se depende de uma gaveta que muda, não cabe (Text(resultado)). Se você errar, o editor avisa — ou sugerindo acrescentar, ou com erro vermelho dizendo que aquilo não pode ser const. É um aviso barato de resolver, não se assuste com ele.

Convertendo texto em número

Como o TextField sempre entrega texto, fazer conta com o que foi digitado exige uma conversão:

de String para número

double preco = double.tryParse(precoDigitado) ?? 0;   // "59.90" -> 59.90
int pessoas = int.tryParse(pessoasDigitado) ?? 1;     // "4"     -> 4
Em bom português

double.tryParse significa "tente transformar este texto em número". Se a pessoa digitou algo que não é número (ou deixou vazio), a tentativa falha e devolve vazio — e aí o ?? 0 entra como valor reserva: "se não deu, use 0". É isso que evita o app quebrar quando alguém digita "abc" no campo de preço.

Cuidado

O Dart usa ponto como separador decimal, não vírgula: 59.90 funciona, 59,90 não converte e cai no valor reserva. Avise isso aos usuários do seu app — ou trate a vírgula antes de converter, com precoDigitado.replaceAll(",", ".").

Validando um cadastro

Este é, de longe, o uso mais comum de if na vida real: conferir o que a pessoa preencheu antes de deixar ela seguir.

Um app raramente lida com um item só: são vários produtos no carrinho, vários pedidos, vários contatos. Para isso existe a lista.

Em bom português

Uma lista (List) é uma fileira numerada de gavetas com a mesma etiqueta. Em vez de item1, item2, item3, você tem uma única itens com várias posições dentro — e pode acrescentar ou remover posições enquanto o app roda.

Lógica · 6Funções

Você já escreveu funções neste material: calcular() é uma. Agora vamos criar as suas próprias para não repetir a mesma conta em vários lugares.

Em bom português

Uma função é uma receita reutilizável: um pedaço de código com nome, que recebe ingredientes (os parâmetros) e devolve um resultado (o retorno). Em vez de reescrever a conta toda vez, você chama a função pelo nome.

regra de desconto numa função só

regiões 1 e 2
// ===== 1. AS GAVETAS =====
String valorDigitado = "";
String tipoCliente = "Novo";
bool aniversariante = false;
String resultado = "";

// ===== 2. A LÓGICA =====
// a função: recebe três ingredientes e devolve o valor final
double aplicarDesconto(double valor, String tipo, bool aniversario) {
  double desconto = 0;

  if (tipo == "Fidelidade") {
    desconto = desconto + 0.10; // 10%
  }
  if (aniversario) {
    desconto = desconto + 0.05; // mais 5%
  }

  return valor - (valor * desconto);
}

void calcular() {
  double valor = double.tryParse(valorDigitado) ?? 0;
  double final_ = aplicarDesconto(valor, tipoCliente, aniversariante);

  setState(() {
    resultado = "De R\$ ${valor.toStringAsFixed(2)}\n"
        "por R\$ ${final_.toStringAsFixed(2)}";
  });
}
Em bom português

Em double aplicarDesconto(double valor, String tipo, bool aniversario): o primeiro double é o tipo do que a função devolve (o return); depois vem o nome; e entre parênteses os parâmetros, os ingredientes que ela recebe. Uma função que não devolve nada usa void, como a calcular().

Cuidado

A variável se chama final_ com um risquinho no fim porque final é palavra reservada do Dart (aquela das gavetas trancadas) e não pode ser usada como nome. Quando o Dart reclamar de um nome, quase sempre é isso: você pegou uma palavra que a linguagem já usa.

No mercado

Separar a regra de negócio numa função é o que permite testá-la sozinha, reaproveitá-la em outra tela e mudá-la num lugar só quando o cliente mudar de ideia. É um dos hábitos que mais separa código profissional de código de iniciante — e você já pode começar com ele.

Mão na massa

Monte a tela de desconto com o campo de valor, uma seleção "Novo/Fidelidade" e a marcação de aniversariante. Depois crie uma segunda função, double calcularFrete(double valor), que devolve 0 se a compra passar de R$ 200 e 24.90 se não passar — e mostre os dois valores no cartão.

Lógica · 7Nulidade segura (null safety)

Este é o conceito mais "de Dart" da lista, e você já o usou sem saber: todo ?? 0 deste material é null safety em ação.

Em bom português

Nulo (null) quer dizer "essa gaveta está vazia": não tem nada dentro, nem zero, nem texto vazio — nada. O Dart tem uma regra chamada null safety (nulidade segura): por padrão nenhuma gaveta pode ficar vazia, e se você quiser permitir isso precisa avisar com um ?.

um campo que pode não ser preenchido

// ===== 1. AS GAVETAS =====
String rua = "";
String numero = "";
String? complemento;   // o "?" avisa: esta gaveta pode ficar vazia
String resultado = "";

// ===== 2. A LÓGICA =====
void calcular() {
  // se estiver vazia, usa o texto reserva
  String textoComplemento = complemento ?? "sem complemento";

  setState(() {
    resultado = "Entrega em: $rua, $numero\n$textoComplemento";
  });
}
Em bom português

Três símbolos resumem o assunto:

  • ? depois do tipo — "esta gaveta pode ficar vazia" (String?).
  • ?? — "se estiver vazia, use este valor reserva". É o que já salvou suas contas quando o campo estava em branco.
  • ! — "eu garanto que aqui não está vazio". Use com cuidado: se você garantir errado, o app quebra na hora. É o que aparece no escolha! dos campos de seleção.
No mercado

"Deu erro de null" é provavelmente a falha mais comum em aplicativos. O Dart obriga você a pensar nisso enquanto escreve, e não quando o usuário reclama — é chato no começo e economiza muito depois.

Cuidado

Não se cobre entender null safety 100% agora. Reconhecer a ideia (gaveta vazia, gaveta com placa de "pode ficar vazia" e valor reserva) já é o suficiente para não travar quando o Dart reclamar. Vamos voltar a isso nas unidades de Flutter.

Mão na massa

Monte uma tela de endereço com rua, número e complemento, sendo o complemento opcional (String?). Mostre o endereço completo no cartão, escrevendo "sem complemento" quando o campo ficar vazio.

import 'package:flutter/material.dart';

  State<Tela> createState() => _TelaState();

class _TelaState extends State<Tela> {

  String pessoasDigitadas = "";

    });
  }

Exemplo 3 — Carrinho com desconto e frete

listas · loop · funções
import 'package:flutter/material.dart';

void main() => runApp(const AppCarrinho());

class AppCarrinho extends StatelessWidget {
  const AppCarrinho({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: "Carrinho",
      theme: ThemeData(colorSchemeSeed: Colors.deepOrange),
      home: const TelaCarrinho(),
    );
  }
}

class TelaCarrinho extends StatefulWidget {
  const TelaCarrinho({super.key});

  @override
  State<TelaCarrinho> createState() => _TelaCarrinhoState();
}

class _TelaCarrinhoState extends State<TelaCarrinho> {
  List<String> nomes = [];
  List<double> precos = [];

  String nomeDigitado = "";
  String precoDigitado = "";
  String tipoCliente = "Novo";
  bool aniversariante = false;
  String resumo = "";

  // soma tudo que está no carrinho
  double somarItens() {
    double total = 0;
    for (int i = 0; i < precos.length; i++) {
      total = total + precos[i];
    }
    return total;
  }

  // a regra de desconto da loja, isolada numa função
  double aplicarDesconto(double valor, String tipo, bool aniversario) {
    double desconto = 0;
    if (tipo == "Fidelidade") desconto = desconto + 0.10;
    if (aniversario) desconto = desconto + 0.05;
    return valor - (valor * desconto);
  }

  double calcularFrete(double valor) {
    return valor >= 200 ? 0 : 24.90;
  }

  void adicionar() {
    double preco = double.tryParse(precoDigitado.replaceAll(",", ".")) ?? 0;
    if (nomeDigitado.isEmpty || preco <= 0) return;

    setState(() {
      nomes.add(nomeDigitado);
      precos.add(preco);
      resumo = "";
    });
  }

  void fecharPedido() {
    if (nomes.isEmpty) {
      setState(() => resumo = "Seu carrinho está vazio.");
      return;
    }

    double subtotal = somarItens();
    double comDesconto = aplicarDesconto(subtotal, tipoCliente, aniversariante);
    double frete = calcularFrete(comDesconto);

    setState(() {
      resumo = "Subtotal: R\$ ${subtotal.toStringAsFixed(2)}\n"
          "Com desconto: R\$ ${comDesconto.toStringAsFixed(2)}\n"
          "Frete: R\$ ${frete.toStringAsFixed(2)}\n"
          "TOTAL: R\$ ${(comDesconto + frete).toStringAsFixed(2)}";
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text("Meu carrinho")),
      body: SingleChildScrollView(
        padding: const EdgeInsets.all(24),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            TextField(
              decoration: const InputDecoration(labelText: "Produto"),
              onChanged: (texto) => nomeDigitado = texto,
            ),
            TextField(
              decoration: const InputDecoration(labelText: "Preço"),
              keyboardType: TextInputType.number,
              onChanged: (texto) => precoDigitado = texto,
            ),
            ElevatedButton(
              onPressed: adicionar,
              child: const Text("Adicionar ao carrinho"),
            ),
            const SizedBox(height: 24),

            Text("${nomes.length} item(ns)",
                style: const TextStyle(fontWeight: FontWeight.bold)),
            for (int i = 0; i < nomes.length; i++)
              Text("• ${nomes[i]} — R\$ ${precos[i].toStringAsFixed(2)}"),

            const SizedBox(height: 24),
            DropdownButton<String>(
              value: tipoCliente,
              isExpanded: true,
              items: const [
                DropdownMenuItem(value: "Novo", child: Text("Cliente novo")),
                DropdownMenuItem(
                    value: "Fidelidade", child: Text("Cliente fidelidade")),
              ],
              onChanged: (escolha) => setState(() => tipoCliente = escolha!),
            ),
            CheckboxListTile(
              title: const Text("Aniversariante do mês"),
              contentPadding: EdgeInsets.zero,
              value: aniversariante,
              onChanged: (marcado) => setState(() => aniversariante = marcado!),
            ),
            ElevatedButton(
              onPressed: fecharPedido,
              child: const Text("Fechar pedido"),
            ),
            const SizedBox(height: 16),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Text(resumo, style: const TextStyle(fontSize: 17)),
              ),
            ),
          ],
        ),
      ),
    );
  }
}

Campo de texto e botão "Adicionar" que vai empilhando tarefas numa lista visível na tela, com o total no topo ("3 tarefas"). Não deixe adicionar texto vazio nem tarefa repetida. Acrescente um botão "Limpar tudo". Treina: listas que crescem, contains e desenhar lista na tela.
